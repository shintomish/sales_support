## 0. 本書の位置づけ

`050_pm_plan.md §9` で議論された「案件マーケット公開化」と「フリーランス技術者向けマッチング」のうち、**最短経路で市場検証** するための PoC（Proof of Concept）計画。

撤退判断を 3〜4 週間以内にできる構成に倒し、本格設計と法務整備（利用規約・特商法・課金）は **検証データが揃ってから** 着手する。

---

## 1. 目的・成功条件

### 1.1 目的
「案件マーケット公開」と「フリーランス技術者集客」が事業として成立しそうかを、**実装最小・観測重視** で見極める。

### 1.2 成功条件（Phase 3 終了時の判定基準）

| 指標 | GO ライン | 要再検討 | 撤退ライン |
|---|---|---|---|
| ユニーク訪問者（3 週間累計） | 200+ | 50〜199 | 50 未満 |
| 案件詳細 PV | 1,000+ | 200〜999 | 200 未満 |
| 「気になる」クリック | 30+ | 5〜29 | 5 未満 |
| Waitlist 登録（フリーランス事前登録） | 50+ | 10〜49 | 10 未満 |

> 上記指標は **本番運用開始から 3 週間** で集計。流入元が偏っている場合（例: 自分の SNS 以外から来ていない）は「需要あり」とは見なさない。

## 3. アーキテクチャ判断（変更しない設計原則）

| 原則 | 理由 |
|---|---|
| **ドメインは分離するがコードは分けない** | `market.ai-mon.net` を Vercel に向け、Next.js middleware で host 判定して `/market/*` のみ通す。撤退時はミドルウェア削除で済む |
| **既存スキーマに列を増やさない** | `engineer_profiles.is_public` 等の既存列で代替。新テーブルは PoC 専用に 3 つだけ追加（撤退時に DROP） |
| **応募機能は作らない** | 「気になる」ボタン + メール捕捉のみ。本人確認・契約・料金回収のドメインに入らない |
| **既存社内システム（`app.ai-mon.net`）は触らない** | Phase 1〜3 通じて社内側のコードは無変更を維持 |
| **課金・法務は完全に後回し** | 利用規約は「PoC のため予告なく終了する場合があります」の 1 行で代替 |

## 4. Phase 1 ─ 公開閲覧 PoC（実装 3〜5 日）

### 4.1 ドメインとルーティング
- DNS: `market.ai-mon.net` を Vercel の既存プロジェクトに alias 追加
- Next.js middleware: host が `market.ai-mon.net` の場合のみ `/market/*` を通し、それ以外（`/customers` 等の社内ページ）は 404 を返す
- 既存 `app.ai-mon.net` は無変更

### 4.2 公開ページ（最小 3 画面）

| ルート | 内容 |
|---|---|
| `/market` | トップ。サービス説明・案件カード 10 件・Waitlist 登録誘導バナー |
| `/market/projects` | 案件一覧（ページネーション + スキル絞り込みのみ） |
| `/market/projects/[id]` | 案件詳細（マスキング適用 + 「気になる」ボタン） |

> 技術者公開（`/market/engineers`）は **Phase 1 では出さない**。需要側（案件閲覧）の反応だけで一次判断する。

### 4.3 API
- 専用エンドポイント `MarketProjectController`（薄いラッパー）を新設
- 既存 `PublicProjectController` には手を入れない
- マスキングは Service 層で実施（顧客名 → 業種帯、`sales_contact` → null、単価 → 下限のみ）

### 4.4 計測
- Vercel Analytics（無料枠）
- 自前ログ用に **`market_events` テーブルを 1 つだけ追加**:
  カラム = `event_type / project_id / session_id / referrer / user_agent / created_at`
- 撤退時は DROP するだけで元に戻せる

## 5. Phase 2 ─ 需要捕捉 PoC（実装 3〜5 日）

### 5.1「気になる」フォーム
- 案件詳細に小さなフォーム（メール + 自由テキスト 1 行）
- 保存先: `market_inquiries` テーブル（`email / project_id / message / created_at`）
- 自動返信メール: 既存 SES 配信基盤を流用（テンプレ「お問い合わせありがとうございます」）
- 通知: y-shintomi@aizen-sol.co.jp に 1 行通知（feedback フォームと同じ流路）

### 5.2 フリーランス Waitlist
- **本登録機能は作らない**。「事前登録」フォームでメール + スキルタグ（チップ式 最大 5 個）を取得
- 保存先: `market_waitlist` テーブル（`email / skills / created_at`）
- 完了画面で「サービス開始時にご連絡します」と表示

> ここで応募機能を作ると、本人確認・契約・課金・特商法表記が一気に発生する。Waitlist で需要だけ測る。

---

## 6. Phase 3 ─ 運用・計測（実装ほぼなし・期間 2〜3 週間）

### 6.1 集客（コードは書かない）
- 新冨個人 SNS（X / LinkedIn）で告知
- 案件メールの一部を SNS でマスキング版で抜粋紹介し、`market.ai-mon.net/projects/[id]` に誘導
- フリーランスエンジニアコミュニティ（Slack 系）への手動投稿

### 6.2 撤退時の処理（撤退ラインに該当した場合）

下記 4 ステップで剥がせる（既存社内システムには影響なし）:

1. DNS で `market.ai-mon.net` のレコード削除
2. `src/middleware.ts` の host 判定ブロックを削除
3. `/market/*` ページ群を削除
4. `market_events / market_inquiries / market_waitlist` の 3 テーブルを DROP

## 7. やらないこと（PoC スコープ外を明記）

| 項目 | 理由 |
|---|---|
| ✗ 課金組み込み（Stripe 等） | 撤退時の戻しが重い。需要が見えてから |
| ✗ 利用規約・特商法ページ | PoC は無料・限定運用なので 1 行表示で代替 |
| ✗ フリーランスの本登録・応募機能 | 本人確認・契約管理が連鎖発生する |
| ✗ 発注企業向け案件登録 UI | 社内入力で十分。発注側オンボーディングは需要確認後 |
| ✗ `public_projects.commission_rate` 列追加 | 手数料が発生しない PoC では不要 |
| ✗ 認証分離 | read-only なので不要 |
| ✗ Aizen 以外のテナント案件公開 | 責任分界点が曖昧になる |
