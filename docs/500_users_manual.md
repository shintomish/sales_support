## 1. はじめに

### 1.1 本マニュアルの目的

営業支援システム（Sales Support System）の社内利用にあたり、画面操作の基本と各機能の使い方をまとめたガイドです。  
PPT 化して新規利用者向けの説明資料として活用できる構成にしています。

### 1.2 対象ユーザー

- 営業担当者（メール処理・配信・マッチング業務）
- 経理担当者（SES 契約・請求書発行）
- 管理者（テナント・ユーザー管理）

### 1.3 アクセス先

| 環境 | URL |
|---|---|
| 本番 | https://app.ai-mon.net |
| 開発（参考） | （社内告知済 URL） |

### 1.4 SES プラン限定機能・管理者限定機能の表記

本マニュアルでは、テナント設定で SES 機能を有効化したテナントのみ利用できる項目に **【SES限定】**、管理者ロール（`super_admin` / `tenant_admin`）のみ利用できる項目に **【管理者限定】** を付与しています。

#### 【SES限定】の意味

**SES（System Engineering Service / 準委任契約）業務を行うテナント向け機能**です。  
技術者派遣・案件マッチング・SES 契約管理・請求書発行のフローが必要な利用企業のみが使う想定で、CRM 機能（顧客・商談・タスクなど）だけを使う一般テナントには表示されません。

| 制御項目 | 内容 |
|---|---|
| 切替フラグ | `tenants.ses_enabled`（DB カラム） |
| 切替権限 | テナント管理者 |
| 表示制御 | サイドバー（`Sidebar.tsx` の `sesOnly: true` フラグ）で動的に出し分け |
| 自社状態 | アイゼン・ソリューションは `ses_enabled = true` のため全機能利用可 |

#### 【SES限定】対象機能

- 請求書管理（SES台帳 / 勤務表 / 請求書作成 / 請求書一覧 / 請求書送信履歴）
- マーケット（案件 / 技術者）
- 案件メール / 技術者メール
- 配信管理
- 設定 → 請求書発行元設定

#### 【管理者限定】対象機能

- ユーザー管理 / データ統計（`super_admin` または `tenant_admin` のみ）

## 2. ログインとパスワード管理

### 2.1 ログイン

1. ブラウザで `https://app.ai-mon.net` を開く
2. 登録済みのメールアドレスとパスワードを入力
3. 「ログイン」をクリック

### 2.2 パスワードを忘れた場合

1. ログイン画面下部の「パスワードを忘れた方はこちら」をクリック
2. 登録メールアドレスを入力 → 送信
3. 受信メールのリンクからパスワードリセット画面へ
4. **新パスワードを入力して確定**（下記ルールを満たすこと）

#### 新パスワードの入力ルール

| 要件 | 内容 |
|---|---|
| 文字数 | **8 文字以上** |
| 大文字 | **A〜Z を 1 文字以上** 含む |
| 小文字 | **a〜z を 1 文字以上** 含む |
| 数字 | **0〜9 を 1 文字以上** 含む |
| 確認入力 | 確認用パスワード欄と一致していること |
| 履歴 | 前回と同じパスワードは使用不可（エラー: `same_password`）|

> リセット画面ではリアルタイムでチェック項目（✓/×）が表示されます。すべて ✓ になり、確認入力が一致すると「変更する」ボタンが有効になります。

#### 推奨例

- `MyDog2026Sun` / `Aiz2026Sales` のように **独自フレーズ＋数字** を組み合わせる
- `password123` `qwerty2026` `tanaka1990` など推測しやすいものは避ける

> 認証メールは `outsource@aizen-sol.co.jp` から送信されます（AWS SES 経由・日本語テンプレート）。

### 2.3 ログアウト

サイドバー下部のユーザー情報直下にある **「↩ ログアウト」** ボタンをクリック。

## 3. ダッシュボード

ログイン直後に表示される画面。CRM の主要 KPI と直近の動きを一目で把握できます。

### 3.1 主な表示要素

| 要素 | 内容 |
|---|---|
| KPI カード（4枚） | 総顧客数 / 進行中の商談 / 今月の成約件数 / 今月の売上（万円） |
| クイックアクション | 顧客登録 / 担当者登録 / 商談登録 / 活動記録 / タスク追加 へのショートカット |
| 月別売上 棒グラフ | 過去 6 ヶ月の売上推移 |
| 商談パイプライン 円グラフ | 商談ステータスごとの件数（新規 / 提案 / 交渉 / 成約 / 稼働中 / 失注） |
| 期限が近いタスク | 期限超過は「超過」バッジ、当日は「今日」バッジ。優先度カラー（高/中/低） |
| 直近の活動履歴 | 訪問・電話・メール・その他、種別アイコン付き |
| 今月の成約 | 商談タイトル・顧客名・成約額 |

### 3.2 サイドバーからの通知

未読メール件数や期限切れタスク件数は **サイドバー側のバッジ** で通知されます（ダッシュボード本体の表示要素ではありません）：

- 未読メール: サイドバー「メール」アイコンの赤バッジ
- 期限切れタスク: サイドバー下部の赤カード + トースト通知
- **承認待ち／差戻し**【SES限定】: サイドバー「承認サマリー」リンクに doc_type 別（請求書／見積書／注文書）の件数バッジ。リンクをクリックすると既読化され、次回ログイン後に再度未読の通知が発生するまで非表示になる（2026-05-13 追加）

### 3.3 サイドバーの折りたたみ（2026-05-14 追加）

24 インチ（1920×1080）など狭めの画面で一覧画面が収まらない問題への対策として、サイドバー上部に **▶/◀ トグルボタン** を追加しました。

| 状態 | 幅 | 表示内容 |
|---|---|---|
| 展開（既定） | `w-64` | 通常のメニュー（グループヘッダー・通知サマリーカード・ユーザー情報） |
| 折りたたみ | `w-16` | アイコンのみ。グループヘッダー省略、通知サマリーカード／ユーザー情報は非表示。サブ項目は直接縦並びで表示 |

- 折りたたみ状態は **`localStorage`（キー: `sidebar_collapsed`）** に永続化され、次回ログイン時も維持されます。
- 合わせて以下の画面の `max-w-7xl` を撤廃し、横幅をフル活用できるようにしました（狭幅時は横スクロールで対応）：
  - 配信管理（`/deliveries`, `/deliveries/campaigns/[id]`）
  - 帳票一覧 3 種（`/invoices`, `/estimates`, `/purchase-orders`）

> md 未満（スマホ幅）でのドロワー化と、単体メール一覧画面の改修は後続フェーズ（#29 スマホ対応）で対応します。

## 4. CRM

### 4.1 顧客管理（`/customers`）

#### 機能
取引先企業マスタ（Customer）の登録・編集・検索。商談 / 担当者 / 活動履歴 はすべてこのマスタに紐付きます。

#### 主な操作
- **一覧**: 検索（会社名）/ 並び替え / フィルタ
- **新規登録**: 「+ 新規登録」ボタンから登録フォームへ
- **編集**: 一覧の行をクリック → 詳細画面 → 「編集」
- **削除**: 詳細画面の「削除」ボタン（関連データに注意）

#### 請求書送付関連の項目（2026-05-08 追加）

| 項目 | 内容 |
|---|---|
| 請求送付方法（`invoice_delivery_method`） | `mail`（メール）/ `post`（郵送）/ `both`（両方）のいずれかを選択。請求書詳細画面の「メール送信」「郵送記録」ボタンの活性制御に利用 |
| 担当者 1（メイン） | 既存の `primary_contact_id`。送付状の宛名と封筒の名前に使用 |
| 担当者 2〜5（`secondary_contact_ids`） | 同じ取引先の追加担当者を最大 4 名まで紐付け可能。請求書のメール送信時に CC 候補として表示 |

> 担当者 2〜5 は `customers.secondary_contact_ids`（JSON 配列）で管理されます。担当者マスタ（`/contacts`）から個別に登録した上で、顧客編集画面で割り当ててください。

#### 顧客マスタの増加経路

| 経路 | Customer マスタへの登録 |
|---|---|
| 手動登録（本画面） | ◯ 直接作成 |
| 名刺管理の取込（§9） | ◯ **自動作成・自動紐付け**（OCR で抽出した会社名で検索 → 既存なし時に新規作成） |
| 案件メールの取込 | ✗ 文字列カラム（`project_mail_sources.customer_name`）として抽出されるのみで、**顧客マスタとの自動紐付けは行いません**。必要に応じて手動でマスタ登録してください |

### 4.2 担当者管理（`/contacts`）

#### 機能
取引先の担当者個人を管理。顧客に紐付け。

#### 主な操作
- 顧客選択 → 担当者を新規登録
- ※ OCR による自動登録は §9 名刺管理から実行（本画面では手動登録のみ）
- メールアドレス重複チェックあり

### 4.3 商談管理（`/deals`）

#### 機能
案件単位の商談（ディール）を管理。ステータスで進行状況を追跡。

#### 主なステータス（8種）
- 新規 / 提案 / 交渉 / 成約 / 失注 / 稼働中 / 更新交渉中 / 期限切れ

> ダッシュボードのパイプライン円グラフでもこのステータス順で表示されます。

#### 主な操作
- 顧客 + 案件タイトル で新規作成
- 商談ステータスを更新（一覧またはドラッグ＆ドロップ）
- 関連メール / 活動履歴 / タスク を商談画面から登録

### 4.4 活動履歴（`/activities`）

#### 機能
顧客・担当者・商談に対する営業アクション（電話・訪問・メールなど）を記録。

#### 主な操作
- 「+ 活動を記録」 → 種別・日時・メモを入力
- フィルタ: 顧客別 / 担当者別 / 期間別
- ダッシュボードで直近活動を確認

### 4.5 タスク管理（`/tasks`）

#### 機能
営業タスクの登録・期限管理。期限超過タスクはサイドバーに赤バッジで通知。

#### 主な操作
- 新規タスク登録（期限・優先度・担当者）
- ステータス更新（未着手 / 進行中 / 完了）
- 期限超過のフィルタ表示: `?due_filter=overdue`

> 期限切れタスクが発生すると、ダッシュボードとサイドバー両方にトースト通知が表示されます。

## 5. 請求書管理【SES限定】

> 本グループは SES 契約機能を有効化したテナントのみ表示されます。  
> 2026-05-08〜09 にかけて **PDF 体裁の刷新・電子印・承認ワークフロー・送付状/封筒・メール送信・郵送記録・送信履歴** を追加しました。

### 5.1 SES台帳（`/ses-contracts`）

#### 機能
SES 契約（技術者派遣）の管理台帳。技術者・顧客・契約期間・単価を一元管理。

#### 主な操作
- 新規 SES 契約の登録（技術者・顧客・開始日・単価・精算条件）
- 契約一覧の検索（顧客名・技術者名・タイトル：ilike 部分一致）
- 契約期間更新・終了処理
- **注文 No.（`order_number`）の登録**（2026-05-08 追加）: 顧客側の発注番号を任意項目として保持。請求書 PDF の上部に表示

#### フィルタ・表示の改善（2026-05-14 追加）

- **「期限切れも表示」チェックボックス**を検索フィルタ横に追加。既定 **OFF** で期限切れ案件はリストから除外され、ON（`include_expired=1`）で復帰します。
- 期限切れバッジの配色を **薄灰 → 紅茶色（rose-50 / 800 / 200）** に変更し、視認性を改善しました。

#### Excel インポートと自動期限切れ化（2026-05-14 追加）

- Excel から SES 契約を一括取込できます。インポート完了後のモーダルは **3 列 → 4 列構成** に拡張され、「**完了扱い**」枠（Excel に未掲載で自動的に期限切れ扱いになった件数）が表示されます。
- Excel に **掲載されていない有効契約は自動的に期限切れ（`status='expired'`）** に更新されます。重複や取り違えを防ぐためのガードとして機能します。

### 5.2 勤務表（`/timesheets`）

#### 機能
SES 契約ごとの月次稼働時間を入力・管理。

#### 主な操作
- **年月セレクト**で対象月を切替（YYYY-MM 単位）
- 各 SES 契約の **実労働時間 / 超過時間** を入力（一括更新可能）
- 削除ボタンで該当月のレコードを削除

> 超過時間は請求書 PDF の「超過控除」セクションと請求金額の自動計算に利用されます。
> なお、**「請求書あり」チェックと「請求書受領日」フィールドは 2026-05-14 に削除されました**（運用で使われなかったため）。

### 5.3 請求書作成（`/billing-summaries`）

> 旧称「請求集計」を 2026-05-08 に **「請求書作成」** にリネームしました（メニュー名のみ変更・URL は据え置き）。

#### 機能
月次請求の集計表示と請求書発行のスタートポイント。SES 契約と勤務表から金額を自動計算し、その場で `/invoices` 配下のレコードを生成します。

#### 主な操作
- 集計対象月を選択
- 集計単位を切替（案件 / 顧客）
- 顧客ごとの請求金額を確認
- **「請求書を発行」で `/invoices` レコードを作成**（同じ案件×年月は重複不可）
  - 発行日（`issued_date`）の初期値は **対象年月の月末**
  - 業務交通費は **非課税（`is_expense = true`）** として明細に追加
  - 発行元情報（会社名・住所・印影・URL 等）と精算条件を **発行時にスナップショット**

#### 自動計算ロジック

`BillingCalculationService` が以下を計算：

| 項目 | 計算式 |
|---|---|
| 基本額 | SES 契約の `income_amount` |
| 控除 | `max(0, client_deduction_hours - actual_hours) × client_deduction_unit_price` |
| 超過 | `max(0, actual_hours - client_overtime_hours) × client_overtime_unit_price` |
| 消費税 | 10% 固定（業務交通費は除外） |

> **注意**: 勤務表の実労働時間（`actual_hours`）が未入力の月は **控除・超過は 0 として扱われます**。請求発行前に勤務表の入力を済ませてください。

#### Refinitiv 注文書 PDF から請求書発行（2026-05-13 追加）

Refinitiv（リフィニティブ・ジャパン）からの注文書 PDF を取込んで請求書ドラフトを発行する専用フロー。`/billing-summaries` 画面の右上にある **オレンジボタン「📋 Refinitiv注文書から請求書発行」** から開きます。

| ステップ | 内容 |
|---|---|
| 1. PDF アップロード | ドラッグ＆ドロップ or ファイル選択。Claude Sonnet 4 が PO Number・申請者・申請番号・Plant.ID・分類コード・依頼納期・「その他の情報」欄を自動抽出 |
| 2. 抽出結果の確認・編集 | 「PO Number」「Description」「Requested Delivery Date」「Plant ID/Name」「Classification Code」等を画面で編集可能 |
| 3. 紐付け対象 SES案件 / 年月の選択 | テナント内の SES契約を絞込（既定: リフィニティブ）し、対象年月を指定 |
| 4. 「請求書ドラフトを作成」 | 英文モード（`language='en'`）の請求書ドラフトが発行される。`order_number` には PO Number が入り、その他の情報は `vendor_metadata` (JSONB) に保持される |

> 発行後は通常の請求書ドラフトと同じく `/invoices/{id}` で編集・PDF 生成・送信が可能。`vendor_metadata` が入っている請求書は **Refinitiv 専用 PDF レイアウト** で出力されます（英文 / 注文情報セクション付き）。
> 詳細フロー・抽出フィールド一覧は [`docs/070_refinitiv_invoice_flow.md`](070_refinitiv_invoice_flow.md) を参照。

### 5.4 請求書一覧（`/invoices`）

#### 機能
請求書の作成・編集・PDF 発行・送付・送信履歴管理。  
ステータスは **下書き（`draft`）** / **発行済（`issued`）** の 2 段階＋ **承認フラグ（`approved`）** で管理します。

#### ステータスと承認

| ステータス | 意味 | 編集 | 削除 |
|---|---|---|---|
| `draft`（下書き） | PDF 未発行・編集中 | ◯ | ◯ |
| `issued`（発行済） | PDF 生成済 | ◯（明細・備考なども更新可） | ✗（不可）|

| 承認フラグ | 意味 | PDF 再生成 | メール送信 |
|---|---|---|---|
| 未承認 | 内容確認中 | ◯ | ✗（無効）|
| 承認済 | 発行確定 | ✗（無効）| ◯ |

> 承認は **`super_admin` または `tenant_admin`** のみ実行可能。承認済の請求書は内容変更を防ぐため、PDF 再生成ボタンが無効化（ホバー時に「承認済の請求書は再生成できません」と表示）されます。

> **電子印（丸印）の廃止（2026-05-14 社長指示）**: 請求書・注文書の PDF には **電子印を押印しません**。承認後は PDF を印刷し、紙ベースで物理的に承認印を押した上で、スキャンして PDF 化し、メール送信モーダル（§5.4 末尾）または郵送記録モーダルから添付・送付してください。承認／却下のワークフロー自体は記録のために継続します。見積書の角印は従来通り作成時に自動押印されます。

#### 検索・フィルタ
- 年月（YYYY-MM、**初期値は当月-1**）/ 顧客 / ステータス / キーワード（請求書番号・顧客名）

#### 一覧の主な操作

| 操作 | 内容 |
|---|---|
| 新規発行 | 案件 × 年月 から作成（同じ案件＋年月の組み合わせは重複不可。通常は §5.3 から） |
| 編集 | 発行日 / 支払期限 / 備考 / 明細（説明・数量・単位・単価・税率 0% / 8% / 10% / `is_expense`）|
| **複写**（2026-05-14 追加） | 既存の請求書を当月扱いで複写し、新しい請求書番号で下書きを開く。明細は全コピー、`due_date` は未設定、承認・PDF・送信履歴は持ち越さない |
| PDF 生成 | 「PDF を発行」ボタン → 生成・ストレージ保存 → status が `issued` に自動遷移（請求書・注文書では電子印は押印されません / §5.4 注記参照） |
| 承認 / 解除 | 詳細画面のトグルで切替（管理者ロールのみ） |
| 削除 | `draft` のみ可 |

> **明細表記の簡素化（2026-05-14）**: 基本月額の明細行は **金額のみ**（例：`350,000円`）で保持されます。PDF 出力時に「・基本月額：」ラベルが自動付与されます。
> **PDF 超過控除セクション（2026-05-14）**: SES台帳に超過控除データ（`client_deduction_*` / `client_overtime_*`）が何もない場合、超過控除セクション自体が PDF に出力されません。ラベルから「(中間割)」「(10円未満切り捨て)」の注記も削除されました。
> **複写ボタン（2026-05-14）**: 同じ仕様で **見積書一覧（`/estimates`）／注文書一覧（`/purchase-orders`）** にも追加されています。doc_type に応じた番号体系（EST/ORD/INV）で当月採番されます。

### 8.3 キャンペーン作成

#### 主な操作
1. 件名・本文を入力（プレースホルダ `<%Name%>` は配信時にバックエンドで配信先名に自動置換）
2. 「配信先リストへ一括送信」をクリック
3. **元請けドメイン重複チェック**: 入手元メール (紐づき案件メールの from、または手動入力した「入手元アドレス」) と同一ドメインで `is_active=true` の配信先がある場合、赤い警告モーダルが表示されます (詳細は §8.3.1)
4. バックグラウンドで送信開始

> 配信中の進捗（成功・失敗の件数）は配信履歴一覧の各キャンペーン詳細画面で確認できます。

#### 8.3.1 元請けドメイン重複警告 (2026-05-18 追加)

SES 案件メールを **元請け企業 (案件発信元) に送り返すと「抜き額（中間マージン）」が露呈する**事故を防ぐためのガードです。

**発火条件**: 入手元アドレス (`source_email` / 紐づき案件メールの `from_address`) のドメインと同じドメインで `is_active=true` の配信先が 1 件以上あるとき。

**モーダル表示内容**:
- 入手元アドレス・ドメイン
- 同一ドメインのアクティブ配信先一覧（最大 10 件、超過分は件数表示）
- ☑️ 「今回これら N 件を除外して配信」チェックボックス（**既定 ON**）
- 「キャンセル」 / 「除外して配信」 / 「配信する」 ボタン

**除外送信の挙動**:
- チェック ON で「除外して配信」を押すと、該当配信先を **今回のキャンペーンのみ送信対象から除外**します
- 配信先の `is_active` 状態は変更されない (= 次回送信時は通常通り含まれる)
- バックエンドは `exclude_address_ids[]` を `WHERE id NOT IN (...)` で適用するため、`is_active=true/false` の書換ミスや復元漏れリスクはありません

> チェックを OFF にして「配信する」を押せば、警告を承知の上で全件配信することも可能です。

#### 添付ファイル（2026-05-08 整備）

- 添付ファイルは Supabase Storage に保存され、キャンペーン詳細から **元のファイル名でダウンロード**できます
- 旧データで添付ファイル名が `unknown` になっていたものは `2026_05_08_140000_backfill_unknown_attachment_filenames` で適切な名前にバックフィル済み

### 8.4 送信履歴・再送信

`delivery_send_histories` に保存。  
送信成功・失敗・返信紐づけを `send_type` 別に確認可能。

- 送信日時 / 再送信日時を **「日付」「時刻」の 2 行表示**（列幅 `w-[90px]` ・`whitespace-nowrap` 固定）。再送信日時が空でもヘッダーが縦書きにならないように調整。

## 9. 名刺管理（`/business-cards`）

### 9.1 機能

紙の名刺を画像アップロード → Google Vision API（OCR）→ 担当者・顧客・メールアドレスを自動抽出。

### 9.2 主な操作

| 操作 | 内容 |
|---|---|
| 単一画像のアップロード | **1 リクエストで最大 50 枚**まで（自動回転対応 / 各画像 **10MB 以下** / JPEG・PNG） |
| 複数名刺モード | **1 枚の画像内に並んだ複数名刺**を Vision API で **自動グリッド分割**。1 画像から取得できる枚数に上限なし（画像内の名刺数に依存・実用例 6〜12 枚） |
| OCR 抽出 | 会社名・氏名・部署・役職・郵便番号・住所・電話・FAX・携帯・メール・URL を自動抽出 |
| **顧客・担当者の自動登録** | OCR 抽出結果から **顧客（Customer）** と **担当者（Contact）** の両方を自動作成（既存があれば紐付け／更新） |
| 重複検出 | 同一会社＋同一氏名（異体字許容）の既存名刺があれば、上書き更新 |

#### 自動登録の流れ

```
名刺画像アップロード
  ↓
Vision API で OCR 抽出（会社名・氏名・連絡先など）
  ↓
① 顧客（Customer）を会社名で検索
   - 完全一致 → 既存顧客として紐付け
   - 類似度 80% 以上 → 既存顧客として紐付け（「株式会社」等を除いた Levenshtein 比較）
   - 該当なし → 新規顧客として登録（is_new_customer = true）
   - 会社名なしの個人名刺 → 「氏名（個人）」として登録
  ↓
② 担当者（Contact）を作成または更新し、上記の顧客に紐付け
   - 同顧客 × メール一致 → 既存担当者を更新
   - 同顧客 × 氏名一致（空白除去・異体字正規化） → 既存担当者を更新
   - いずれも該当なし → 新規担当者を作成
  ↓
レスポンスで「顧客 ID」「担当者 ID」「新規顧客フラグ」を返却
```

#### OCR 抽出項目 → 各モデルへの登録対応

OCR で抽出される項目のうち、**実際に顧客／担当者マスタに保存されるのは限定的**です。残りは名刺マスタ（`business_cards`）にのみ保管されます。

| OCR 抽出項目 | 名刺（BusinessCard） | 顧客（Customer） | 担当者（Contact） |
|---|---|---|---|
| 会社名 | ✅ company_name | ✅ company_name（新規作成時） | — |
| 氏名 | ✅ person_name | （会社名なしの個人時のみ `氏名（個人）`） | ✅ name |
| 部署 | ✅ department | — | — |
| 役職 | ✅ position | — | ✅ position |
| 郵便番号 | ✅ postal_code | — | — |
| 住所 | ✅ address | ✅ address（新規作成時／差分があれば更新） | — |
| 電話 | ✅ phone | ✅ phone（新規作成時／差分があれば更新） | — |
| 携帯 | ✅ mobile | （個人顧客時のみ phone として登録） | ✅ phone（**携帯優先**・mobile → phone の順） |
| FAX | ✅ fax | — | — |
| メール | ✅ email | — | ✅ email |
| URL | ✅ website | — | — |

> **注意点**:
> - 部署・FAX・URL・郵便番号は名刺マスタに残るのみで、顧客／担当者マスタには伝搬しません
> - 既存顧客が見つかった場合、`company_name` は元の表記を尊重して更新しません（`phone` `address` のみ差分更新）
> - 担当者の電話番号は **携帯（mobile）を優先**し、無い場合のみ電話（phone）を使用します

### 9.3 注意点

| 項目 | 値 |
|---|---|
| 対応形式 | JPEG / PNG（HEIC は事前に変換） |
| 1 リクエスト上限 | 50 枚 |
| 1 画像サイズ上限 | 10MB |
| 大量取込時 | 50 枚を超える場合は **複数回に分けて並列リクエスト** を推奨 |
| 抽出精度 | 印刷の鮮明さ・撮影状況に依存 |
| 複数名刺画像 | 自動グリッド分割（commit `e6d1720`） |

## 10. 設定

### 10.1 メール署名設定（`/settings/email-template`）

#### 機能
配信メール・提案メールの差出人署名を編集。

#### 主な操作
- テキスト形式で署名本文を編集
- プレースホルダ `<送信者氏名>` `<送信者部署>` などを利用
- 保存後、新規キャンペーンに自動適用

#### 注意点（未置換プレースホルダのチェック）

キャンペーン送信時、件名や本文に **`<送信者氏名>` などの山括弧プレースホルダ** が残っているとエラーになり送信できません。送信前に必ず最終確認してください。

エラー時の表示例：

> 未置換のプレースホルダがあります: `<送信者氏名>`

| プレースホルダ | 置換タイミング | 備考 |
|---|---|---|
| `<送信者氏名>` `<送信者部署>` 等 | 送信前にユーザー側で署名設定から手動置換 | 残っているとエラーで送信不可 |
| `<%Name%>` | 配信時にバックエンドが配信先名で自動置換 | エラー対象外 |

→ 署名設定後にメール本文を確認し、`<送信者…>` が残っていないことを必ずチェックしてください。

### 10.2 請求書発行元設定（`/settings/invoice-issuer`）【SES限定】

#### 機能
発行する **請求書・見積書・注文書**・送付状・封筒・送信メール に使用する発行元情報（自社情報）を設定。

#### 入力項目
- 会社名・住所・電話番号・FAX 番号
- **ホームページ URL（`invoice_issuer_url`）**（2026-05-08 追加）— 送付状・PDF フッタ・メール署名に表示
- 適格請求書発行事業者番号（インボイス対応）

未入力のタブは組込みデフォルト文面が使用されます（API: `GET /api/v1/invoices/{id}/mail-template`）。

#### 英文情報セクション（2026-05-13 追加・Refinitiv 等の英文取引向け）

英文モード（`language='en'`）の請求書 PDF・Refinitiv フローで使用する英訳項目。空欄なら日本語項目で代用されます。

| 入力欄 | DB カラム |
|---|---|
| 会社名 (EN) | `invoice_issuer_name_en` |

#### 注意点
- 入力した発行元情報は、**請求書を発行（PDF生成）した時点でスナップショット**されます。後から発行元情報を変更しても、過去の発行済請求書には影響しません（`invoices.issuer_*_snapshot` カラム群）。

## 12. よくある質問・トラブルシューティング

### 12.1 ログイン関連

**Q. パスワードリセットメールが届かない**  
A. 迷惑メールフォルダを確認。SES 経由で送信のため `outsource@aizen-sol.co.jp` を許可リスト追加。

**Q. ログイン後すぐにログアウトされる**  
A. ブラウザの Cookie 設定を確認。第三者 Cookie ブロックを解除。

### 12.2 メール関連

**Q. Gmail のメールが取り込まれない**  
A.  
1. 設定で Gmail OAuth が有効か確認
2. 自動同期は 15 分間隔。手動同期は不要（廃止）
3. それでも取り込まれない場合は管理者に連絡

**Q. 技術者メールなのに案件メールに分類された**  
A. キーワード未網羅の可能性あり。管理者に該当メールの件名と本文の特徴を共有してください。分類ロジックは `EmailClassificationService` で随時拡張可能。

### 12.3 配信関連

**Q. 配信先リストの一部にメールが届かない**  
A.  
1. `is_active = false` になっていないか確認（unsubscribe リクエスト時に自動 OFF）
2. SES バウンス履歴を確認（管理者メニュー）
3. `outsource@aizen-sol.co.jp` への返信が滞留している場合は KAGOYA 側を確認

**Q. 配信中に進捗が止まる**  
A. ダッシュボードの「配信中」表示が更新されているか確認。サーバー側のキャッシュキー `campaign_sending_{id}` が残っていれば送信継続中。

### 12.4 マッチング関連

**Q. 期待した技術者がマッチング候補に出ない**  
A.  
- 希望単価未記載・35万/月未満は除外対象
- 案件 `unit_price_max` が技術者希望 `unit_price_max` 以上である必要あり
- 詳細は `docs/420_matching_requirements.md` を参照

### 12.5 操作・表示の不具合

問題発生時は **`/settings/feedback`（不具合・要望を送る）** から報告してください（§10.4 参照）。  
画面 URL とブラウザ情報は自動添付されます。以下を本文に書いてもらえると対応がスムーズです：

1. 操作内容（どの画面でどのボタンを押したか）
2. 発生したこと（エラー文言・画面挙動）
3. 期待していたこと
4. 再現するか（毎回 / たまに）
5. スクリーンショット（可能であれば別途 LINE 等で共有）
