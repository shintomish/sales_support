## 1. はじめに

### 1.1 本マニュアルの目的

営業支援システム（Sales Support System）の社内利用にあたり、画面操作の基本と各機能の使い方をまとめたガイドです。  
PPT 化して新規利用者向けの説明資料として活用できる構成にしています。

### 1.2 対象ユーザー

- 営業担当者（メール処理・配信・マッチング業務）
- 経理担当者（SES 契約・請求書発行）
- 管理者（テナント・ユーザー管理）

### 1.3 アクセス先

| 環境 | URL |
|---|---|
| 本番 | https://app.ai-mon.net |
| 開発（参考） | （社内告知済 URL） |

### 1.4 SES プラン限定機能・管理者限定機能の表記

本マニュアルでは、テナント設定で SES 機能を有効化したテナントのみ利用できる項目に **【SES限定】**、管理者ロール（`super_admin` / `tenant_admin`）のみ利用できる項目に **【管理者限定】** を付与しています。

#### 【SES限定】の意味

**SES（System Engineering Service / 準委任契約）業務を行うテナント向け機能**です。  
技術者派遣・案件マッチング・SES 契約管理・請求書発行のフローが必要な利用企業のみが使う想定で、CRM 機能（顧客・商談・タスクなど）だけを使う一般テナントには表示されません。

| 制御項目 | 内容 |
|---|---|
| 切替フラグ | `tenants.ses_enabled`（DB カラム） |
| 切替権限 | テナント管理者 |
| 表示制御 | サイドバー（`Sidebar.tsx` の `sesOnly: true` フラグ）で動的に出し分け |
| 自社状態 | アイゼン・ソリューションは `ses_enabled = true` のため全機能利用可 |

#### 【SES限定】対象機能

- 請求書管理（SES台帳 / 勤務表 / 請求書一覧 / 請求集計）
- マーケット（案件 / 技術者）
- 案件メール / 技術者メール
- 配信管理
- 設定 → 請求書発行元設定

#### 【管理者限定】対象機能

- ユーザー管理 / データ統計（`super_admin` または `tenant_admin` のみ）

## 2. ログインとパスワード管理

### 2.1 ログイン

1. ブラウザで `https://app.ai-mon.net` を開く
2. 登録済みのメールアドレスとパスワードを入力
3. 「ログイン」をクリック

### 2.2 パスワードを忘れた場合

1. ログイン画面下部の「パスワードを忘れた方はこちら」をクリック
2. 登録メールアドレスを入力 → 送信
3. 受信メールのリンクからパスワードリセット画面へ
4. **新パスワードを入力して確定**（下記ルールを満たすこと）

#### 新パスワードの入力ルール

| 要件 | 内容 |
|---|---|
| 文字数 | **8 文字以上** |
| 大文字 | **A〜Z を 1 文字以上** 含む |
| 小文字 | **a〜z を 1 文字以上** 含む |
| 数字 | **0〜9 を 1 文字以上** 含む |
| 確認入力 | 確認用パスワード欄と一致していること |
| 履歴 | 前回と同じパスワードは使用不可（エラー: `same_password`）|

> リセット画面ではリアルタイムでチェック項目（✓/×）が表示されます。すべて ✓ になり、確認入力が一致すると「変更する」ボタンが有効になります。

#### 推奨例

- `MyDog2026Sun` / `Aiz2026Sales` のように **独自フレーズ＋数字** を組み合わせる
- `password123` `qwerty2026` `tanaka1990` など推測しやすいものは避ける

> 認証メールは `outsource@aizen-sol.co.jp` から送信されます（AWS SES 経由・日本語テンプレート）。

### 2.3 ログアウト

サイドバー下部のユーザー情報直下にある **「↩ ログアウト」** ボタンをクリック。

### 3.1 主な表示要素

| 要素 | 内容 |
|---|---|
| KPI カード（4枚） | 総顧客数 / 進行中の商談 / 今月の成約件数 / 今月の売上（万円） |

## 4. CRM

### 4.1 顧客管理（`/customers`）

#### 機能
取引先企業マスタ（Customer）の登録・編集・検索。商談 / 担当者 / 活動履歴 はすべてこのマスタに紐付きます。

#### 主な操作
- **一覧**: 検索（会社名）/ 並び替え / フィルタ
- **新規登録**: 「+ 新規登録」ボタンから登録フォームへ
- **編集**: 一覧の行をクリック → 詳細画面 → 「編集」
- **削除**: 詳細画面の「削除」ボタン（関連データに注意）

#### 顧客マスタの増加経路

| 経路 | Customer マスタへの登録 |
|---|---|
| 手動登録（本画面） | ◯ 直接作成 |
| 名刺管理の取込（§9） | ◯ **自動作成・自動紐付け**（OCR で抽出した会社名で検索 → 既存なし時に新規作成） |
| 案件メールの取込 | ✗ 文字列カラム（`project_mail_sources.customer_name`）として抽出されるのみで、**顧客マスタとの自動紐付けは行いません**。必要に応じて手動でマスタ登録してください |

### 4.2 担当者管理（`/contacts`）

#### 機能
取引先の担当者個人を管理。顧客に紐付け。

#### 主な操作
- 顧客選択 → 担当者を新規登録
- ※ OCR による自動登録は §9 名刺管理から実行（本画面では手動登録のみ）
- メールアドレス重複チェックあり

### 4.3 商談管理（`/deals`）

#### 機能
案件単位の商談（ディール）を管理。ステータスで進行状況を追跡。

#### 主なステータス（8種）
- 新規 / 提案 / 交渉 / 成約 / 失注 / 稼働中 / 更新交渉中 / 期限切れ

> ダッシュボードのパイプライン円グラフでもこのステータス順で表示されます。

#### 主な操作
- 顧客 + 案件タイトル で新規作成
- 商談ステータスを更新（一覧またはドラッグ＆ドロップ）
- 関連メール / 活動履歴 / タスク を商談画面から登録

### 4.4 活動履歴（`/activities`）

#### 機能
顧客・担当者・商談に対する営業アクション（電話・訪問・メールなど）を記録。

#### 主な操作
- 「+ 活動を記録」 → 種別・日時・メモを入力
- フィルタ: 顧客別 / 担当者別 / 期間別
- ダッシュボードで直近活動を確認

### 4.5 タスク管理（`/tasks`）

#### 機能
営業タスクの登録・期限管理。期限超過タスクはサイドバーに赤バッジで通知。

#### 主な操作
- 新規タスク登録（期限・優先度・担当者）
- ステータス更新（未着手 / 進行中 / 完了）
- 期限超過のフィルタ表示: `?due_filter=overdue`

> 期限切れタスクが発生すると、ダッシュボードとサイドバー両方にトースト通知が表示されます。

## 5. 請求書管理【SES限定】

> 本グループは SES 契約機能を有効化したテナントのみ表示されます。

### 5.1 SES台帳（`/ses-contracts`）

#### 機能
SES 契約（技術者派遣）の管理台帳。技術者・顧客・契約期間・単価を一元管理。

#### 主な操作
- 新規 SES 契約の登録（技術者・顧客・開始日・単価・精算条件）
- 契約一覧の検索（顧客名・技術者名・タイトル：ilike 部分一致）
- 契約期間更新・終了処理

### 5.2 勤務表（`/timesheets`）

#### 機能
SES 契約ごとの月次稼働時間を入力・管理。

#### 主な操作
- 月選択 → 各 SES 契約の稼働時間を入力（YYYY-MM 単位）
- 一括更新可能
- 削除ボタンで該当月のレコードを削除

### 5.3 請求書一覧（`/invoices`）

#### 機能
請求書の作成・編集・PDF 発行・一覧管理。  
ステータスは **下書き（`draft`）** / **発行済（`issued`）** の 2 段階管理です。

#### ステータス

| ステータス | 意味 | 編集 | 削除 |
|---|---|---|---|
| `draft`（下書き） | PDF 未発行・編集中 | ◯ | ◯ |
| `issued`（発行済） | PDF 生成済 | ◯（明細・備考なども更新可） | ✗（不可）|

> PDF を生成すると status が **`draft` → `issued` に自動遷移**します。

#### 主な操作

| 操作 | 内容 |
|---|---|
| 検索・フィルタ | 年月（YYYY-MM）/ 顧客 / ステータス / キーワード（請求書番号・顧客名） |
| 新規発行 | 案件 × 年月 から作成（同じ案件＋年月の組み合わせは重複不可） |
| 編集 | 発行日 / 支払期限 / 備考 / 明細（説明・数量・単位・単価・税率 0% / 8% / 10%）|
| PDF 生成 | 「PDF を発行」ボタン → 生成・ストレージ保存 → status が `issued` に自動遷移 |
| 削除 | `draft` のみ可。`issued` は削除不可（誤発行時は明細修正で対応） |

> 送付管理・入金管理は本一覧では扱わず、別途運用で管理してください（将来拡張候補）。

### 5.4 請求集計（`/billing-summaries`）

#### 機能
月次請求の集計表示。SES 契約と勤務表（実労働時間）から自動計算。

#### 主な操作
- 集計対象月を選択
- 集計単位を切替（案件 / 顧客）
- 顧客ごとの請求金額を確認
- 「請求書を発行」で `/invoices` への自動連携（同じ案件×年月は重複不可）

#### 自動計算ロジック

`BillingCalculationService` が以下を計算：

| 項目 | 計算式 |
|---|---|
| 基本額 | SES 契約の `income_amount` |
| 控除 | `max(0, client_deduction_hours - actual_hours) × client_deduction_unit_price` |
| 超過 | `max(0, actual_hours - client_overtime_hours) × client_overtime_unit_price` |
| 消費税 | 10% 固定 |

> **注意**: 勤務表の実労働時間（`actual_hours`）が未入力の月は **控除・超過は 0 として扱われます**。請求発行前に勤務表の入力を済ませてください。

## 6. マーケット【SES限定】

### 6.1 案件（`/public-projects`）

#### 機能
登録案件の管理。手動登録 / 案件メール由来の取込から作成。

#### 主な操作
- **一覧**: 検索（タイトル・説明：ilike 部分一致）/ ステータス絞り込み
- **新規登録**: タイトル・説明・単価・勤務地・必要スキル・案件主
- **編集**: 詳細画面から
- **マッチング**: 案件詳細から「マッチング候補を表示」

#### スキル指定
ProjectRequiredSkill を介して必要スキルを複数登録可能。

### 6.2 技術者（`/engineers`）

#### 機能
登録技術者の管理。プロフィール・スキル・希望条件・名刺画像。

#### 主な操作
- **一覧**: 検索（名前・所属：ilike 部分一致）/ スキル絞り込み
- **新規登録**: 3 タブ構成
  - 基本情報（氏名のみ必須）
  - スキル（経験年数・習熟度）
  - 希望条件（単価・稼働日・勤務形態）
- **マッチング**: 技術者詳細から「マッチング候補案件を表示」

#### マッチング判定ロジック
詳細は [`docs/420_matching_requirements.md`](420_matching_requirements.md) を参照。  
重要な前提:
- 希望単価未記載・35万/月未満の技術者は本番マッチング対象から除外
- マッチ案件表示条件: `案件.unit_price_max >= 技術者希望.unit_price_max`

## 7. メール

### 7.1 メール（`/emails`）

#### 機能
受信メールの一覧表示。Gmail OAuth 連携で 15 分間隔の自動取込。

#### 表示要素
- 未読バッジ（サイドバーのメールアイコンにも表示）
- 件名・差出人・受信日時
- カテゴリラベル: `engineer`（技術者メール）/ `project`（案件メール）/ `other`

#### 主な操作
- 検索（件名・差出人・本文：ilike 部分一致）
- カテゴリで絞り込み
- 既読/未読切り替え
- 添付ファイルダウンロード（メール詳細から）
- 個別削除（関連レコードも一括削除）

#### Gmail 連携
初回利用時は `/api/v1/gmail/callback` で OAuth 認証を実施。  
詳細フローは [`docs/410_feature_design.md`](410_feature_design.md) 参照。

### 7.2 案件メール（`/project-mails`）【SES限定】

#### 機能
分類済みの案件メールを案件メール画面でスコアリング表示。

#### スコア判定（詳細: `docs/540_project_mail_flow.md`）
| スコア | ステータス |
|---|---|
| 60点以上 | 新着案件 |
| 40〜59点 | 要確認 |
| 39点以下 | 除外 |

#### 主な操作
- ステータスで絞り込み
- 詳細画面で「案件確定」「除外」操作
- 「提案メール」ボタンから配信フローへ
- 全件再スコア（手動）

#### 本文キーワードハイライト

詳細画面でメール本文を表示する際、**スコア理由（`score_reasons`）から抽出したキーワード**を **黄色背景**（`#fef08a`）でハイライト表示します。営業担当が判定根拠を一目で確認できます。

##### ハイライト対象のカテゴリ

| カテゴリ | 例 |
|---|---|
| 技術: 言語（`lang:`） | Java / PHP / Python / TypeScript / Go |
| 技術: FW・インフラ（`infra:`） | **Spring** / **AWS** / Docker / Laravel / Kubernetes |
| 技術: DB（`db:`） | PostgreSQL / MySQL / MongoDB |
| 案件ワード（`project_a:` / `project_b:`） | 案件ご紹介 / 単価 / 稼働開始 / 募集 |
| 工程（`process:`） | 設計 / 実装 / テスト |
| 時期（`timing:`） | 即日 / 長期 |
| ペナルティ（`penalty_vague:` / `penalty_chain:`） | 応相談 / 4次請け |

##### ハイライト対象外

| 項目 | 理由 |
|---|---|
| 勤務地名（`location:` 東京・大阪 等） | 案件カードの住所列と重複するため意図的に除外 |
| ドメイン補正（`domain:`） | キーワードでなく送信元学習値のため |
| `excluded` / `price_concrete` | フラグのため対応キーワードなし |
| 勤務形態（リモート可・常駐 等） | `score_reasons` ではなく `work_style` カラムで管理 |
| URL 内の文字列 | `cc.php` の `php` 誤マッチ防止のため対象外 |

### 7.3 技術者メール（`/engineer-mails`）【SES限定】

#### 機能
分類済みの技術者メールをスコアリング表示。スキル抽出・添付（スキルシート）の解析。

#### スコア判定（詳細: `docs/530_engineer_mail_flow.md`）
| スコア | ステータス |
|---|---|
| 60点以上 | 新着 |
| 40〜59点 | 要確認 |
| 39点以下 | 除外 |

#### 主な操作
- ステータス変更ボタン
- **「技術者として登録→」ボタン**: 技術者管理に自動プリフィル登録
- 全件再スコア（手動・添付解析スキップ）

#### 本文キーワードハイライト

詳細画面でメール本文を表示する際、**抽出されたスキル一覧**を **緑系背景**（`#ccfbf1` / 文字色 `#0f766e`）でハイライト表示します。

- ハイライト対象: 「Java」「Laravel」「AWS」など、技術スキル抽出ロジックがマッチしたワード
- URL 内の文字列はハイライト対象外（誤マッチ防止）

> 分類とスコアリングは別ロジックです（`docs/530_engineer_mail_flow.md` §8 補足参照）。

## 8. 配信管理（`/deliveries`）【SES限定】

### 8.1 機能

一斉配信メール（営業案内・技術者紹介・案件提案）の作成・送信・履歴管理。  
AWS SES（東京リージョン）経由で送信。

### 8.2 配信先リスト

#### 主な操作
- CSV インポートで一括登録
- 配信停止リクエスト（unsubscribe）の自動反映
- 個別の `is_active` フラグでオプトアウト

### 8.3 キャンペーン作成

#### 主な操作
1. 件名・本文を入力（プレースホルダ `<%Name%>` は配信時にバックエンドで配信先名に自動置換）
2. 「送信」をクリック
3. バックグラウンドで送信開始

> 配信中の進捗（成功・失敗の件数）は配信履歴一覧の各キャンペーン詳細画面で確認できます。

### 8.4 送信履歴

`delivery_send_histories` に保存。  
送信成功・失敗・返信紐づけを `send_type` 別に確認可能。

### 8.5 提案スレッド

`/api/v1/proposal-threads` 経由で、案件メール・技術者メールに紐づく送信履歴をスレッド化表示。  
返信メールの未読有無も視覚化。

### 8.6 配信枠

| 項目 | 値 |
|---|---|
| AWS SES 本番承認 | 2026-04-17 |
| 当面の運用目標 | 日次 12,000 通 / 月次 240,000 通 |
| 送信レート | 14 通/秒（実装は 100ms 間隔の安全マージン） |

詳細: [`docs/450_distribution_management.md`](450_distribution_management.md)

## 9. 名刺管理（`/business-cards`）

### 9.1 機能

紙の名刺を画像アップロード → Google Vision API（OCR）→ 担当者・顧客・メールアドレスを自動抽出。

### 9.2 主な操作

| 操作 | 内容 |
|---|---|
| 単一画像のアップロード | **1 リクエストで最大 50 枚**まで（自動回転対応 / 各画像 **10MB 以下** / JPEG・PNG） |
| 複数名刺モード | **1 枚の画像内に並んだ複数名刺**を Vision API で **自動グリッド分割**。1 画像から取得できる枚数に上限なし（画像内の名刺数に依存・実用例 6〜12 枚） |
| OCR 抽出 | 会社名・氏名・部署・役職・郵便番号・住所・電話・FAX・携帯・メール・URL を自動抽出 |
| **顧客・担当者の自動登録** | OCR 抽出結果から **顧客（Customer）** と **担当者（Contact）** の両方を自動作成（既存があれば紐付け／更新） |
| 重複検出 | 同一会社＋同一氏名（異体字許容）の既存名刺があれば、上書き更新 |

#### 自動登録の流れ

```
名刺画像アップロード
  ↓
Vision API で OCR 抽出（会社名・氏名・連絡先など）
  ↓
① 顧客（Customer）を会社名で検索
   - 完全一致 → 既存顧客として紐付け
   - 類似度 80% 以上 → 既存顧客として紐付け（「株式会社」等を除いた Levenshtein 比較）
   - 該当なし → 新規顧客として登録（is_new_customer = true）
   - 会社名なしの個人名刺 → 「氏名（個人）」として登録
  ↓
② 担当者（Contact）を作成または更新し、上記の顧客に紐付け
   - 同顧客 × メール一致 → 既存担当者を更新
   - 同顧客 × 氏名一致（空白除去・異体字正規化） → 既存担当者を更新
   - いずれも該当なし → 新規担当者を作成
  ↓
レスポンスで「顧客 ID」「担当者 ID」「新規顧客フラグ」を返却
```

#### OCR 抽出項目 → 各モデルへの登録対応

OCR で抽出される項目のうち、**実際に顧客／担当者マスタに保存されるのは限定的**です。残りは名刺マスタ（`business_cards`）にのみ保管されます。

| OCR 抽出項目 | 名刺（BusinessCard） | 顧客（Customer） | 担当者（Contact） |
|---|---|---|---|
| 会社名 | ✅ company_name | ✅ company_name（新規作成時） | — |
| 氏名 | ✅ person_name | （会社名なしの個人時のみ `氏名（個人）`） | ✅ name |
| 部署 | ✅ department | — | — |
| 役職 | ✅ position | — | ✅ position |
| 郵便番号 | ✅ postal_code | — | — |
| 住所 | ✅ address | ✅ address（新規作成時／差分があれば更新） | — |
| 電話 | ✅ phone | ✅ phone（新規作成時／差分があれば更新） | — |
| 携帯 | ✅ mobile | （個人顧客時のみ phone として登録） | ✅ phone（**携帯優先**・mobile → phone の順） |
| FAX | ✅ fax | — | — |
| メール | ✅ email | — | ✅ email |
| URL | ✅ website | — | — |

> **注意点**:
> - 部署・FAX・URL・郵便番号は名刺マスタに残るのみで、顧客／担当者マスタには伝搬しません
> - 既存顧客が見つかった場合、`company_name` は元の表記を尊重して更新しません（`phone` `address` のみ差分更新）
> - 担当者の電話番号は **携帯（mobile）を優先**し、無い場合のみ電話（phone）を使用します

### 9.3 注意点

| 項目 | 値 |
|---|---|
| 対応形式 | JPEG / PNG（HEIC は事前に変換） |
| 1 リクエスト上限 | 50 枚 |
| 1 画像サイズ上限 | 10MB |
| 大量取込時 | 50 枚を超える場合は **複数回に分けて並列リクエスト** を推奨 |
| 抽出精度 | 印刷の鮮明さ・撮影状況に依存 |
| 複数名刺画像 | 自動グリッド分割（commit `e6d1720`） |

## 10. 設定

### 10.1 メール署名設定（`/settings/email-template`）

#### 機能
配信メール・提案メールの差出人署名を編集。

#### 主な操作
- テキスト形式で署名本文を編集
- プレースホルダ `<送信者氏名>` `<送信者部署>` などを利用
- 保存後、新規キャンペーンに自動適用

#### 注意点（未置換プレースホルダのチェック）

キャンペーン送信時、件名や本文に **`<送信者氏名>` などの山括弧プレースホルダ** が残っているとエラーになり送信できません。送信前に必ず最終確認してください。

エラー時の表示例：

> 未置換のプレースホルダがあります: `<送信者氏名>`

| プレースホルダ | 置換タイミング | 備考 |
|---|---|---|
| `<送信者氏名>` `<送信者部署>` 等 | 送信前にユーザー側で署名設定から手動置換 | 残っているとエラーで送信不可 |
| `<%Name%>` | 配信時にバックエンドが配信先名で自動置換 | エラー対象外 |

→ 署名設定後にメール本文を確認し、`<送信者…>` が残っていないことを必ずチェックしてください。

### 10.2 請求書発行元設定（`/settings/invoice-issuer`）【SES限定】

#### 機能
発行する請求書の発行元情報（自社情報）を設定。

#### 入力項目
- 会社名・住所・電話番号・FAX 番号
- 適格請求書発行事業者番号（インボイス対応）
- 銀行口座情報（銀行名・支店・種別・番号・口座名義）
- ロゴ画像（PNG / JPG / GIF / WebP / 2MB まで）

#### 注意点
- 入力した発行元情報は、**請求書を発行（PDF生成）した時点でスナップショット**されます。後から発行元情報を変更しても、過去の発行済請求書には影響しません。
- ロゴ画像はテナント単位で管理。未設定の場合は環境変数 `INVOICE_LOGO_PATH`（サーバー固定パス）が使用されます。

## 12. よくある質問・トラブルシューティング

### 12.1 ログイン関連

**Q. パスワードリセットメールが届かない**  
A. 迷惑メールフォルダを確認。SES 経由で送信のため `outsource@aizen-sol.co.jp` を許可リスト追加。

**Q. ログイン後すぐにログアウトされる**  
A. ブラウザの Cookie 設定を確認。第三者 Cookie ブロックを解除。

### 12.2 メール関連

**Q. Gmail のメールが取り込まれない**  
A.  
1. 設定で Gmail OAuth が有効か確認
2. 自動同期は 15 分間隔。手動同期は不要（廃止）
3. それでも取り込まれない場合は管理者に連絡

**Q. 技術者メールなのに案件メールに分類された**  
A. キーワード未網羅の可能性あり。管理者に該当メールの件名と本文の特徴を共有してください。分類ロジックは `EmailClassificationService` で随時拡張可能。

### 12.3 配信関連

**Q. 配信先リストの一部にメールが届かない**  
A.  
1. `is_active = false` になっていないか確認（unsubscribe リクエスト時に自動 OFF）
2. SES バウンス履歴を確認（管理者メニュー）
3. `outsource@aizen-sol.co.jp` への返信が滞留している場合は KAGOYA 側を確認

**Q. 配信中に進捗が止まる**  
A. ダッシュボードの「配信中」表示が更新されているか確認。サーバー側のキャッシュキー `campaign_sending_{id}` が残っていれば送信継続中。

### 12.4 マッチング関連

**Q. 期待した技術者がマッチング候補に出ない**  
A.  
- 希望単価未記載・35万/月未満は除外対象
- 案件 `unit_price_max` が技術者希望 `unit_price_max` 以上である必要あり
- 詳細は `docs/420_matching_requirements.md` を参照

### 12.5 操作・表示の不具合

問題発生時は以下の情報を管理者に共有してください：

1. 発生した URL
2. 操作内容
3. ブラウザ・OS のバージョン
4. スクリーンショット（可能であれば）
